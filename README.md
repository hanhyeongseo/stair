# NIGHT V — 야간 위험 단차 영역 표시

`render_sparse_overlay_demo.py`는 원본 배경을 유지합니다.
`/sparse-overlay/`에서는 양쪽 영상 모두 원래 재생 FPS를 유지하고 오른쪽에만 주황 후보를 표시합니다.
모델의 저장된 마스크 중 초당 5회 시점만 선택하며, 그 사이 프레임은 optical flow로 표시를 추적합니다.
화면 배경에 밝기 보정은 적용하지 않습니다. 분석 입력의 밝기 보정은 기존과 같습니다.
가중치를 다시 학습하거나 실시간 추론 성능을 측정하는 작업은 아닙니다.

영상 업로드 시 파일 SHA256·모델 SHA256·보정 입력 설정이 일치하면 기존에 실제 분석한
`dark`의 원본/결과 비교 영상을 재사용합니다. ‘저장된 동일 파일 분석 결과 · 9초부터 끝까지’로
표시하며 새로 실시간 추론했다고 표시하지 않습니다. 파일명이 같아도 내용이 다르거나 모델·입력
설정이 바뀌면 재사용하지 않습니다. 프레임 속도 등 기술 정보는 기본 결과 화면에 나열하지 않습니다.

## 주황 표시 및 발표 영상 안정화

현재 대시보드의 단차 후보는 주황 윤곽선과 6%의 옅은 채우기로 표시합니다.
위험도를 판정해 빨강으로 바꾸는 기능은 없으며, 사진의 노란 모서리 보조선은 숨겼습니다.
모델 가중치는 변경하지 않았습니다.

`render_orange_demo.py`는 dark의 9초 이후 모든 프레임에 대해 원래 예측과 표시 보정 결과를
별도로 저장합니다. `/orange-demo/`에서 발표용 영상과 좌우 비교 영상을 볼 수 있습니다.
카메라 움직임을 optical flow로 반영한 뒤 약한 시간 평균을 적용하며, 현재 계단 영역 밖에서는
표시를 지웁니다. 잠깐의 미검출은 최대 2프레임만 연결합니다. 이 보정은 약 30fps 발표 영상에만
적용하며, 일반 최대 1fps 영상 분석에는 적용하지 않습니다. 모델 정확도의 향상을 뜻하지 않습니다.
원래 마스크는 `outputs/dark_demo/mask_cache/<체크포인트 해시>/`에 보존해 표시 변경에 재사용합니다.

## 발표용 사전 분석 영상

`render_dark_demo.py`는 dark 영상의 9초 이후를 프레임 생략 없이 분석하고 원본 FPS로 저장합니다.
결과만 보는 영상과 원본/결과 비교 영상을 각각 H.264 MP4로 만듭니다.
이 과정의 처리 속도는 실시간 속도를 의미하지 않습니다. 결과에 ‘사전 분석 결과’를 표시합니다.
이전 마스크 복제·프레임 보간·표시 영역의 수동 보정은 하지 않습니다. 미검출과 마스크 흔들림도 남습니다.
분석 입력은 기존 영상과 같은 긴 변 최대 640픽셀, 출력은 긴 변 최대 1280픽셀, 오디오는 없습니다.
프레임별 오버레이 JPG는 `outputs/dark_demo/frames`에 저장하고, 가중치 해시·입출력 FPS·원본 프레임
번호를 `outputs/dark_demo/report.json`에 기록합니다. 재학습이나 원본 파일 변경은 하지 않습니다.

```powershell
& .\.venv\Scripts\python.exe .\render_dark_demo.py 'C:\영상경로\dark.mp4' --start 9
```

완료 후 `/dark-demo/`에서 재생·다운로드할 수 있습니다. 기존 일반 영상 분석은 여전히 최대 1fps입니다.

## 핀 실패 사진 재학습 실험

**현재 활성 모델: pinned_review_v2.** 기존 가중치에서 이어서 학습한 후보를 전후 비교 후 반영했습니다.
보정 입력, mask IoU ≥ 0.5 기준:

| 자료 | 재학습 전 | 재학습 후 |
|---|---:|---:|
| 핀 사진 44장 (현재 학습 자료) | 5장 | 33장 |
| 동작 유지 확인 10장 (일부 초기 모델 학습 이력 있음) | 9장 | 8장 |
| 핀 이외 학습 사진 42장 | 38장 | 39장 |

핀 사진에서 잘못된 후보는 38개에서 8개로 줄었지만, 미검출은 1장에서 3장으로 늘었습니다.
이 수치를 새로운 계단에서의 정확도로 보고하지 않습니다. 시험·검증을 학습으로 옮겼기 때문에
예전 56장 시험 수치는 현재 모델에 적용하지 않습니다. 원본 라벨·초기 manifest·기존 모델을 보존했습니다.

`prepare_pin_experiment.py`는 원래 manifest를 바꾸지 않고 별도 실험 분할을 만듭니다.
핀 고정한 44장과 같은 촬영 번호의 노출 쌍은 모두 학습 쪽으로 묶었습니다.
재학습: 원본 86장 + 보정본, 검증 10장 + 보정본. 핀 사진의 손실 가중치는 2입니다.
Mask2Former 전체 영역 모델은 고정하고 위험 단차 모델을 새로 학습합니다.

원래 시험 사진 28장과 검증 사진 일부가 이제 학습에 포함됩니다. 남은 park 28장도 학습
사진과 같은 출처여서 새 장소 시험으로 해석하지 않습니다. 핀에서의 개선은 학습 재현이며,
일반화 검증에는 아직 보지 않은 장소의 라벨 있는 사진·영상이 필요합니다.
목록의 train/val/test 표시는 초기 YOLO 자료 분할입니다. 현재 모델의 실험 분할은
`data/experiments/pinned_review_v1/manifest.json`에 별도로 기록합니다.

```powershell
# 아래는 이 저장소 루트 기준 명령입니다.
& .\.venv\Scripts\python.exe .\prepare_pin_experiment.py
& .\.venv\Scripts\python.exe .\train_hazard_head.py --manifest data/experiments/pinned_review_v1/manifest.json --name mask2former_hazard_review_v1 --epochs 50 --pins data/experiments/pinned_review_v1/pins.json --pin-weight 2 --positive-weight 3
& .\.venv\Scripts\python.exe .\evaluate_pin_review.py
& .\.venv\Scripts\python.exe .\activate_pin_review.py
```

활성화는 핀 평균 IoU가 0.05 이상 개선되고 검증 평균 IoU 하락이 0.10 이하일 때만 합니다.
두 입력(원본/보정)의 평균으로 확인하며 남은 park 자료는 가중치나 활성화 선택에 사용하지 않습니다.
이 기준은 제품 안전이나 새로운 계단에서의 충분한 정확도를 뜻하지 않습니다.
이전 모델은 `models/backups/before_pin_review_v1`에 보관합니다.
전후 비교 페이지: `/mask2former/pin-review/`.
활성화 후에는 예전 공유 ZIP의 위험 단차 가중치와 달라지므로 팀 전달용 ZIP도 다시 만들어야 합니다.

첫 실험(v1, 새 가중치부터 학습)은 핀 사진에서는 개선됐으나 다른 사진의 성능 저하로 채택하지 않았습니다.
두 번째 실험(v2)은 기존 가중치에서 이어서 학습하고, 핀 이외 학습 사진에서는 기존 모델의
확률 출력을 참고하는 distillation 손실을 추가했습니다. 학습률은 0.0001입니다.
이 실험의 검증 10장 중 일부는 초기 모델이 과거에 학습한 사진이므로, 해당 검증은
기존 동작 보존을 확인하는 자료이며 완전히 보지 않은 자료의 성능을 뜻하지 않습니다.

사진 검토: 기본 화면의 보유 사진 옆 핀 버튼으로 재라벨링할 사진을 모을 수 있습니다.
선택은 `outputs/review_selection/pins.json`에 저장돼 새로고침·서버 재시작 후에도 유지됩니다.
개별 원본 또는 원본 ZIP을 다운로드하며, 원본이 없으면 축소본으로 대체하지 않고 오류를 표시합니다.
ZIP은 원본 파일명을 source 폴더별로 보존하고 `review_selection.json`에 기존 split을 기록합니다.
핀 고정 자체는 모델·라벨·데이터 분할을 바꾸지 않습니다. 시험·검증 사진을 재학습에 넣는 경우
해당 사진은 이후 독립 평가에서 제외하고, 수정 라벨은 별도로 검사한 뒤 데이터셋을 다시 준비해야 합니다.

**팀원은 먼저 [설치·실행 안내](TEAM_SETUP.md)를 확인하세요.** 이 저장소에는 코드만 있으며,
사진·라벨·가중치·가상환경·분석 결과는 포함하지 않습니다. 아래는 개발 PC 기준 실험 기록입니다.

별도 파일 전달과 모델 ZIP 생성 방법: [팀 공유 안내](SHARING.md).
영상 결과는 브라우저용 H.264 MP4로 저장하며 `/videos`에서 다시 볼 수 있습니다.

## 위험 단차 모델 추가

기존 Mask2Former의 파란 영역과 별도로 **빨간 위험 단차 후보**를 추가했습니다.
기본 화면의 ‘표시’에서 위험 단차/계단 전체를 전환하고 ‘정답 겹치기’로 비교할 수 있습니다.
주황선은 계단 영역 내부의 Canny/Hough 모서리 후보이며 단 개수나 확정된 모서리가 아닙니다.

Mask2Former의 픽셀 디코더 특징은 고정하고, 작은 합성곱 모델을 기존 단차 라벨로 학습했습니다.
학습 원본 57장과 밝기 보정본, 검증 원본 11장과 보정본을 사용했습니다.
최대 60 epoch 중 검증 평균 mask IoU로 가중치와 문턱값을 선택했습니다.
시험 사진 56장은 학습·문턱값 선택에 사용하지 않았습니다. 다만 이전 개발에서 이미 살펴본
시험 자료이므로 새로운 장소에 대한 독립적인 안전 검증으로 해석하지 않습니다.

계단 전체 정답이 없기 때문에 **파란 영역을 대상으로 재학습하지 않았습니다.**
단차 모델은 파란 영역 주변에서만 후보를 표시하고, 원본의 상하행/단 순서를 명시적으로 세지 않습니다.

| 기존 시험 56장, 정답 mask IoU ≥ 0.5 | 위치 일치 | 잘못된 후보 | 평균 mask IoU |
|---|---:|---:|---:|
| 기존 YOLO 서비스 처리 | 9 | 35 | 14.4% |
| 새 단차 모델 · 원본 | 15 | 40 | 32.2% |
| 새 단차 모델 · 밝기 보정 | 22 | 33 | 40.1% |

보정 입력의 precision은 40.0%, recall은 39.3%입니다. 아직 보행 안내에 충분한 성능이 아닙니다.
특히 기존 문제 사례 park (7), (79)는 여전히 IoU 기준을 넘지 못했습니다.
학습자료에 가까운 결과와 새 촬영자료의 결과를 구분해서 봐야 합니다.

결과 페이지: `/mask2former/hazard-results/`.
체크포인트: `models/mask2former_hazard_head.pt`.
학습/평가 기록: `models/hazard_head_training.json`, `outputs/hazard_head_evaluation/report.json`.
평가 보고서는 체크포인트 해시와 일치할 때만 웹의 지표에 표시합니다.
기능 테스트 11개와 실제 사진 업로드·투명 단차 PNG·2프레임 영상 생성/디코딩을 확인했습니다.

```powershell
& .\night_v\.venv\Scripts\python.exe .\night_v\train_hazard_head.py
& .\night_v\.venv\Scripts\python.exe .\night_v\evaluate_hazard_head.py
```

특징 캐시는 추후 실행부터 manifest 해시별로 나눠 라벨 변경 시 재생성합니다.

아래 성능 수치는 기존 YOLO 위험 단차 모델에 대한 것입니다.

**현재 결과:** 학습에서 제외한 park 56장에서 서비스 추론(점수 0.4, mask IoU ≥0.5)은 9개를 맞히고 47개를 놓쳤습니다. 예측 후보 중 위치가 맞지 않은 사례는 35개이며, precision 20.5%, recall 16.1%, 평균 mask IoU 14.4%입니다. 이는 단순 분류 정확도가 아니라 위험 영역 위치 일치 기준입니다. 현재 모델은 다른 계단에서 사용할 수준에 도달하지 못했습니다. 시험 자료로 점수 문턱값을 조절해 결과를 부풀리지 않았습니다.

목표는 전체 계단이나 상행/하행 분류가 아니라, 조원들이 **하행 두 번째 단 / 상행 첫 번째 단**으로 표시한 위험 단차 영역을 찾아 표시하는 것입니다. 이 기준을 가장 가까운 임의의 선으로 바꾸지 않고 그대로 학습했습니다.

## 다른 계단에서의 성능을 위한 분리

**park 촬영 자료 56장 전체는 test**이며 학습이나 최적 epoch 선택에 사용하지 않습니다. 한형서/seo 자료에서는 파일 번호별 밝음/어두움/추가 노출을 묶어 train 57장, val 11장으로 나눴습니다. train에만 밝기 보정 버전을 추가합니다.

이것은 **촬영 자료 단위 홀드아웃**입니다. 실제 장소가 겹치지 않는지 확인되기 전에는 ‘완전히 새로운 장소’ 검증이라고 주장하지 않습니다. 동일 번호만 묶는 것으로 서로 다른 번호의 같은 계단까지 분리되지는 않습니다. 검증/시험 이미지를 학습에 넣어 수치를 올리지 않습니다.

실제 장소 정보가 생기면 `scene_groups.json`에서 번호 묶음을 장소로 연결할 수 있습니다. 예:

```json
{
  "han/han01": "building_A_stair_1",
  "han/han02": "building_A_stair_1",
  "seo/seo01": "building_A_stair_1"
}
```

`prepare.py`는 장소가 분할을 넘으면 중단합니다. 장소가 알려지면 전체 데이터 분할을 다시 검토해야 합니다. park의 동일 장소가 han/seo에 포함돼 있다면 현재 test 또한 새 장소 검증으로 인정할 수 없습니다.

## 학습/검증

GPU: NVIDIA RTX 5060 Laptop. night_v 전용 CUDA PyTorch 환경을 만들었고 rab/수업 환경은 변경하지 않았습니다.

```powershell
# 원본을 읽어서 가져오기·라벨 검사·변환
& .\night_v\.venv\Scripts\python.exe .\night_v\prepare.py --import-sources
# 학습 및 마지막에 홀드아웃 원본 평가
& .\night_v\.venv\Scripts\python.exe .\night_v\train.py --epochs 80 --device 0
# 실제 서비스의 원본+밝기 보정 2-view 추론을 고정 기준으로 평가
& .\night_v\.venv\Scripts\python.exe .\night_v\evaluate.py
```

학습은 공식 YOLO11n-seg 사전학습 가중치에서 시작해 위험 단차 폴리곤을 파인튜닝합니다. 밝기/색상·기울기·크기·좌우 반전을 증강하되 상하 반전은 하지 않습니다. 강한 블랙아웃을 정답 복원으로 간주하지 않습니다.

현재 학습/검증 YAML은 manifest에 근거한 명시적 `train.txt/val.txt/test.txt` 목록을 사용합니다. 따라서 이전 dataset 폴더에 남은 다른 split 파일을 자동으로 추가하지 않습니다. 원본이나 폴더를 재귀 삭제하지 않습니다. 제공 자료를 변경한 뒤에는 manifest와 원본 라벨의 일치 여부를 먼저 확인하세요.

- `models/hazard_best.pt`: 위험 단차 분할 가중치.
- `models/report.json`: 기본 YOLO test mask/box 지표.
- `models/pipeline_evaluation.json`: 서비스와 같은 추론(점수 0.4, mask IoU 0.5)의 홀드아웃 결과. 이 기준을 test를 보고 조절하지 않습니다.
- `outputs/heldout_pipeline`: 빨강 예측과 초록 정답 비교.
- `runs/hazard_seg`: 학습 로그와 checkpoint. 모델 선택은 val만 사용합니다.
